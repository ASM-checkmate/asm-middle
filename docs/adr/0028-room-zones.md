# ADR-0028: 방 안의 캐릭터는 손가락으로도 움직인다 — 트리거 존과 바닥 탭, 위치는 좌표, 걷는 시간은 거리

*   날짜: 2026-09-15
*   상태: 채택됨 (카페는 손으로 잡은 존 4개, 나머지 방은 자리에서 자동으로. 장애물 피하기는 다음)

## 배경

방(ADR-0015)의 캐릭터는 sim이 정한 자리 사이를 로그 큐대로 옮겨 다닌다. 오너는 보기만 하고 아무것도 시킬 수 없다 —
"움직이는 게 통제가 불가능하다". 원하는 것은 둘이다. 누른 곳으로 캐릭터가 걸어가는 것, 그리고 의자 같은 소품 근처에서 그걸
누르면 거기 앉는 식의 상호작용. 그러면서도 커피 마시러 카운터에 가는 것 같은 sim의 자동 이동은 그대로 살아야 한다.

같은 날 오너는 3D 아바타 스파이크(vrm-spike)를 완전히 접었다. 캐릭터는 지금의 얼굴 큰 2D SVG 그림체로 간다.

## 결정

**방 안의 위치를 자리 이름에서 연속 좌표로 바꾸고, 소품 위에 트리거 존을 둔다. 로그 큐·사용자의 탭·살아 있기(산책·잔동작)는
전부 같은 "걸어가서 무언가 한다"를 쓰고, 우선순위는 로그 > 사용자 > 살아 있기다.**

1.  **위치는 좌표, 걷는 시간은 거리 ÷ 속도(120 px/s).** `RoomStage`의 인물은 `{x, y}`를 갖고, 걷기는 CSS transition이 아니라
    requestAnimationFrame이 매 프레임 인물 div의 transform과 z-index(바닥 접점 행)를 직접 쓴다. 걷는 도중 다른 곳을 누르면 그
    자리에서 바로 방향을 튼다. 처음 그릴 때와 도착했을 때만 React 상태가 바뀐다. 다른 인물(동행·손님·배경 인물)은 그대로 transition이다.
2.  **트리거 존(`Zone`)은 소품 위의 누를 수 있는 사각형이다.** 누르면 존의 자리(`spot`)까지 걸어가고, 도착하는 순간 존의 자세(`pose`)를
    취하며 말(`say`)을 띄운다. 두 번 누를 필요가 없다 — "가까이 가서 누르면" 대신 **한 번에 가서 한다**. 대신 인물이 존 자리에서 64px
    안에 있으면 존이 노랗게 빛나고 이름표("주문하기", "창밖 보기")가 떠서 여기서 뭘 할 수 있는지 알린다. 이미 거기 서 있으면 조용하다.
    존은 바닥 위·소품 아래(z 0)에 깔리고, 소품·인물·말풍선은 pointer-events가 없어 탭이 존에 닿는다.
3.  **바닥을 누르면 거기까지 걷고 그냥 선다.** 화면 좌표를 방 좌표로 환산하고(방이 축소돼 있어도), 벽(방의 자리 중 가장 위 행)보다
    위와 가장자리는 바닥 안으로 당긴다. 장애물은 아직 안 피한다 — 테이블을 가로질러 걷는다. 격자 길 찾기는 다음 ADR.
4.  **존은 손으로 잡거나 자리에서 만든다.** 카페는 창가 벤치(생각)·카운터("주문할게요")·내 테이블(자리의 자세 — 그림·읽기·먹기)·
    옆 테이블(앉기)을 손으로 잡았다. `zones`가 없는 방은 `zonesOf`가 내 자리와 산책 목적지(`strolls`)를 각각 인물 한 명 크기 상자의
    존으로 만든다(입구는 뺀다 — 나가는 건 출발의 몫). 그래서 열 방 전부에 존이 있다.
5.  **우선순위와 돌아올 곳.** 로그 큐는 뭘 하고 있든 끊고 간다 — 방은 sim이 사는 곳이다. 사용자 탭은 산책·잔동작을 끊는다. 산책·잔동작은
    이름난 자리에 서서 잠깐 자세도 없이 쉴 때만 끼어든다(내 자리가 아니어도, 단 "한 모금"은 테이블 위 컵이 뜨는 것이라 내 자리에서만).
    큐의 `then`과 산책의 복귀 자리는 사용자가 마지막으로 고른 존이다(없으면 내 자리) — 창가로 보내 두면 커피를 사고 창가로 돌아온다.
    옆 테이블 존을 누르면 거기 앉아 있던 손님은 일어나 나가고, 내가 거기 있는 동안 손님이 안 온다.

## 근거

*   **두 번 탭 대신 한 번.** 오너가 말한 것은 "근처에 가면 트리거되고, 누르면 앉는다"였다. 모바일에서 두 번 누르는 건 번거롭고,
    같은 데이터(존 = 자리 + 자세)로 한 번 탭도 되니 한 번으로 하고 "근처에서 빛남"을 피드백으로 남겼다.
*   **엔진은 그림체를 모른다.** 좌표·존·우선순위는 방 데이터와 `RoomStage`의 로직이고 SVG를 건드리지 않는다. 팔 모양·표정 레이어를
    바꿔도(다음 작업) 여기는 그대로다.
*   **rAF 직접 쓰기.** transition은 도중에 끊으면 현재 위치를 모른다(computed transform을 파싱해야 한다). rAF는 위치를 알고 있고,
    매 프레임 React를 돌리지 않아 96px SVG 캐릭터가 무겁지 않다.
*   버린 것: 소품 svg에 `interact`를 붙이는 방식 — 창은 뒷벽 svg의 일부라 소품이 아니고, 히트 영역이 그림 크기와 다를 때가 많아
    존을 따로 두는 게 맞았다. 사용자 탭이 로그 큐보다 우선하는 것 — 활동 로그가 곧 방의 사건인데 사용자가 붙들고 있으면 사건이 안 보인다.

## 영향

*   `room/Room.tsx`: `Zone`, `RoomSpec.zones?`, `zonesOf`, 자리 이름표 표. `room/RoomStage.tsx`: 좌표·rAF 걷기·탭·우선순위.
    `room/cafe.tsx`: 존 4개. `room/room.css`: 존·이름표, 내 캐릭터의 transition 제거.
*   시간표의 기다리는 방(ADR-0015 개정 2)도 같은 무대라 거기서도 움직일 수 있다. 출발(`leaving`) 뒤 탭은 무시한다.
*   남는 일: 격자 + A* 길 찾기(테이블 돌아가기), 옆으로 걷는 3/4 옆모습(클릭 이동으로 옆걸음이 많아졌다), 존마다 다른 잔동작.
*   QA: `?preview=active:cafe&p=0.5`에서 카운터·창가·테이블을 눌러 본다. 헤드리스로는 CDP `Input.dispatchMouseEvent`로 방 좌표에
    탭을 넣고 프레임을 찍는다(스크립트는 shot.mjs 기반, 이 PR엔 안 넣음).
