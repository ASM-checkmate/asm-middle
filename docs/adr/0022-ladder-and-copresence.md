# ADR-0022: 관계는 세 단계, 같은 공간에 있던 것은 같이 논 게 아니다

*   날짜: 2026-09-11
*   상태: 제안됨 (SNS 브랜치. 구현 전)

## 배경

친구는 마주침(같은 곳 30분 + 대화 롤)으로만 생기고(FRIENDS_SPEC §4), 친구가 되면 내 빈 블록을 채워 같이 논다(§2). SNS(ADR-0021)가 생기면
"글이 보이는 사람", "대표컷이 보이는 사람", "채팅이 되는 사람"이 각각 언제 열리는지 정해야 한다. 그리고 오너가 명확히 한 원칙:
**같은 공간에 있었지만 말을 안 했으면 같이 논 게 아니다.** 사진에도 같이 안 나온다 — 나오더라도 멀리, 옆모습만.

## 결정

**관계는 스친 사이 → SNS 친구 → 친한 친구 세 단계다. 입구는 마주침 하나뿐이고, 같이 놀았으면 무조건 SNS 친구다.
같은 공간(co-present)과 같이 놀기(companion)는 데이터·사진·글에서 전부 갈린다.** 표는 FRIENDS_SPEC §6.

1.  **세 단계.** 스친 사이(대화 실패, 이름만) → SNS 친구(대화 성공 = 그 자리에서 SNS 교환; 글·대표컷·좋아요·일정 채우기) →
    친한 친구(같이 논 N회, 초기값 3; 채팅·"알게 된 것").
2.  **SNS에 친구 맺기 버튼은 없다.** ID 검색·팔로우·요청 없음. 마주치고 → SNS 교환 → 다음 일정 같이 → 알아가기. 같은 활동을 하게 만드는 것이
    목표라 한 번에 여러 친구를 못 사귀게 한다. 마주침은 하루 1명(§4 그대로).
3.  **같이 놀았으면 SNS 친구.** "같이 놀기"는 SNS 친구가 된 뒤에만 생기고, 다른 경로로 같은 활동을 함께 마쳤다면 즉시 자동 친구다.
    "같이 놀았는데 친구 아님"은 존재하지 않는다.
4.  **co-present는 `presentNearby`, companion은 `companions`.** 전자는 그 순간의 사실이지 관계가 아니다. 사진에서 전자는 배경에 옆·뒷모습·작게·
    얼굴 없이(카페 방의 "옆 손님" 자리), 후자는 같은 프레임에 정면·실제 겉모습으로. 글에서 전자는 태그 없음, 후자는 서로 태그.
5.  **활동 중간에 대화가 성공하면** 앞 컷은 옆모습, 뒤 컷은 정면. 찍을 때 굽기(ADR-0020)라 그대로 남는다.
6.  **"알게 된 것".** 같은 활동마다 하나씩 `memory.friends[id].learned[]`. 친한 친구 프로필에 접기 토글(기본 접힘).

## 근거

*   **사진이 관계를 말한다.** 배경의 옆모습이 며칠 뒤 정면이 되는 걸 사진만 넘겨도 알 수 있다. 이게 벡터를 버린(ADR-0020) 이유이기도 하다.
*   **프라이버시가 규칙에서 나온다.** 배경 인물은 얼굴이 없으니 비공개 계정 사람이 남의 사진에 노출되는 일이 원천적으로 없다. 별도 가림 처리가 필요 없다.
*   **버린 안: 우정 축과 별개의 "같이 논 사이" 단계.** 처음 제안은 SNS 친구와 같이 논 사이를 나눴는데 오너가 지적했다 — 같이 놀았는데 SNS 친구가
    아닌 상태는 말이 안 된다. 그래서 같이 놀기는 SNS 친구의 *결과*가 아니라 *권한*이 됐다.

## 영향

*   `ScheduledActivity.presentNearby: string[]` 추가. 마주침 판정(`encounterOf`)이 대화 실패 시에도 여기에 적는다.
*   활동 장면·촬영: 배경 인물 그리기(옆·뒷모습 변형은 ADR-0019의 뒷모습 세트 재사용), 대화 성공 시점부터 정면 전환.
*   FRIENDS_SPEC 동행 표시 규칙의 얼굴 조항은 "우리가 임의로 그리지 않는다 — 본인이 SNS에 올린 대표컷만"으로 재해석했다.
*   `memory.friends[id]`에 `bond`(우정 단계)·`learned[]`. 서버 친구 관계(`POST /api/friends`)는 그대로 — 단계는 로컬 계산이다.
