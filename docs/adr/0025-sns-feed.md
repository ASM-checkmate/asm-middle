# ADR-0025: 홈의 친구 버튼은 SNS가 된다 — 에이전트가 올리고, 주인이 고치고, 추천은 서버가 취향으로 고른다

*   날짜: 2026-09-11
*   상태: 제안됨 (SNS 브랜치. 구현 전)

## 배경

친구 목록(FriendsOverlay)은 이름·동네·만난 곳·지금 뭐 하는지만 보여주는 화면이었다. 사용자 사이에 오가는 건 프로필·발행 일정·친구 관계뿐,
콘텐츠는 없었다(CONTRACT §2.3). 오너의 방향: 각자의 에이전트가 한 활동의 사진으로 글을 올리는 SNS를 만들고, 친구 관리를 그 안으로
넣는다. 주인은 편집할 수 있어야 하고, 사진은 활동 단위로 보관돼 글을 쓸 때 쉽게 찾아 써야 한다.

## 결정

**SNS는 피드·친구·내 글 세 탭이다. 앨범은 책이고, 글쓰기는 책의 고르기 모드다. 글은 에이전트가 하루 하나 올리고 고민이 있을 때만 묻는다.
추천은 서버가 주인의 취향과 인기도로 고른다. 반응은 좋아요만.** 화면·흐름은 design/SNS_SPEC.md.

1.  **앨범을 따로 만들지 않는다.** 책이 이미 활동 단위(만화 하나 = 활동 하나 = 4컷)이고 검색·범주 칩·일/주 묶기(ADR-0016)가 있다.
    글쓰기는 책을 "고르기 모드"로 여는 것이다 — 탭하면 번호, 트레이에 쌓임, 최대 10컷.
2.  **글은 `Post`** — 컷 id 목록(순서 있음, 1~10), 캡션, 추천·검색용 면(장소·동네·도시·범주·날짜), 동행(활동의 `companions`에서만).
    서버 리소스다(`POST /api/posts`, `GET /api/feed`, `POST/DELETE /api/posts/{id}/like`). 남이 읽어야 하므로 opaque 문서에 끼우지 않는다.
3.  **피드는 한 줄기.** 친구 글(가상 친구 포함) → 구분선 → 추천. 친구 수를 일부러 적게 만드는 설계(FRIENDS_SPEC §4·§6)라 친구 탭을 따로
    두면 늘 비어 있다. 컷은 가로 슬라이드.
4.  **추천은 서버가 계산한다.** 취향 재료가 이미 서버에 있다 — 발행 일정(`PUT /api/me/schedule`)의 범주·장소·시간대 분포와 좋아요.
    `점수 = 0.5 취향유사도 + 0.3 인기도 + 0.2 신선도`. 인기도는 `log(1+좋아요)`에 시간 감쇠 — 좋아요 1000이 100의 10배가 아니라 1.5배쯤
    되어야 "중간 가중치"가 유지된다. 탐색 몫 10~15%, 같은 작성자 연속 제한, 본 글 제외, 비공개·친구·자기 자신 제외. 추천 글엔 이유 칩.
    가중치는 서버에서만 바꾼다.
5.  **에이전트가 하루 하나 올린다.** 여유 있는 창(카페·집에서 쉼·20분 이상 이동·자기 전)에 그때까지의 컷으로 초안을 만들어 올린다.
    안 올렸으면 자기 전에. 기본은 묻지 않고 "올렸어" 한 줄, 주인은 사후 수정("주인이 고쳤어요"). **고민이 있을 때만** 채팅으로 이유와 초안을
    보여주고 `그대로 올려` / `컷 고치기` 버튼 — 답이 없으면 15분 뒤 올린다. 고민 조건은 SNS_SPEC §9, 주 2회 상한.
6.  **가상 친구 글은 내 폰이 만든다.** 서버는 가상 친구를 모른다(ADR-0006). 내 시뮬이 걔들 글 시점에 컷을 굽고 내 미디어 저장소에
    `kind: 'npc'`로 올린다. 친구 구간에만 나오고 남의 추천엔 절대 안 나온다.
7.  **계정 공개는 속성.** `public`이면 추천에 노출·누구나 열람, `private`이면 친구만. 어느 쪽이든 친구 맺기 버튼은 없다.
8.  **좋아요만.** 댓글 없음. 차단·신고·용량 정리·계정 전환 캐시는 이 결정에서 뺐다.

## 근거

*   **책이 앨범이다.** 활동 단위 보관과 "필요한 사진만 쉽게 찾기"는 ADR-0016이 이미 풀었다. 두 벌을 만들면 검색·묶기가 갈라진다.
*   **묻는 건 가끔이어야 관계가 된다.** 매일 물으면 알림이다. "물어본다 = 뭔가 있다"가 성립하려면 조건과 상한이 필요하다.
*   **친구 구간을 먼저, 추천을 뒤에.** 인스타의 Following/For You 두 탭을 버린 이유는 친구가 적게 설계돼 있어서다.
*   **버린 안: 마주칠 수 있는 사람 추천.** 오너가 명확히 했다 — 추천은 주인의 취향이고, 마주침 가능성은 거의 중요하지 않다.
    "관심 누르면 에이전트 계획에 영향" 고리도 같이 버렸다.
*   **버린 안: 서버 NPC 계정.** 실제 유저가 적을 때 추천이 얇은 문제는 있지만 시뮬을 서버에 복제하는 건 ADR-0006을 정면으로 어긴다.
    탐색 몫과 인기도로 버티고, 필요해지면 그때 다시 본다.

## 영향

*   FriendsOverlay 삭제 → SNS의 친구 탭 + 프로필. 로그아웃·계정 전환은 책으로 이동.
*   TopChrome 왼쪽 위 버튼 교체(`chrome-friends` → `chrome-sns`), `?preview=sns`.
*   백엔드: posts·likes·feed·visibility, 추천 점수 계산(처음엔 SQL + 메모리 정렬로 충분).
*   채팅에 버튼 달린 메시지 종류가 하나 생긴다(초안 확인). 채팅 프롬프트에 "왜 지금 올리는지" 한 줄이 들어간다.
*   ADR-0024(픽셀·미디어)이 선행 조건이다.
*   **발행 엔진은 `sim/agentPosts.ts`** (순수 논리 + 주입되는 굽기·저장), 스토어의 tick이 `pumpRequests` 뒤에 굴린다(`pumpAgentPost`·`pumpNpcPosts`).
    상태는 `world.agentPost`(v5 저장본의 optional 칸, 부팅 때 `validAgentPost`): `{ lastPostDay?, lastPostAt?, pending?: { draftId, dueAt, asked, draft }, asks: { week, count }, skippedDay?, likedAuthors: Record<authorId, number[]> }`.
    초안(`PostDraft`)은 새로고침에도 살아야 해서 `pending.draft`에 같이 실리고, 글쓰기 화면이 미리 채우도록 `useSns.draft`에도 둔다.
*   쪽지(`AgentRequest`)에 **kind `'post'`** 가 생긴다 — refId = 초안 id, 마감 15분, 답 `post`(그대로 올려, 기본)/`edit`(컷 고치기 → 글쓰기 화면). 마감을 넘기면 `decidedAlone` → 통보 문구는 "답이 없어서 그냥 올릴게"(올리기는 마감 뒤 — 컷 업로드·서버 — 라 올렸다고 하지 않는다), 엔진이 그대로 올리면 "올렸어 · 보러 가기"가 따로 온다. 자정 15분 전에 물어 마감이 자정 뒤여도 그 초안은 버리지 않고 어제 날짜로 올린다.
    글쓰기 화면은 끝나면 `store.resolvePostDraft(draftId, 'posted' | 'discarded', postId?)`를 부른다 — 올렸으면 한 줄만 남기고(다시 올리지 않는다), 버렸으면 `skippedDay`로 그날은 건너뛴다.
*   `ChatMsg.link?: { kind: 'post'; id; label }` — "올렸어" 한 줄 아래 `보러 가기` 칩(ChatOverlay: 내 글 탭을 열고 대화창을 닫는다). 하루에 이 한 줄뿐이다.
*   가상 친구의 글은 localStorage **`theworld.snslocal.v1`** (`{ v: 1, items: FeedItem[] }`, 최신 30편, sync.ts LOCAL_KEYS에 있어 아이디가 바뀌면 같이 비운다) — 부팅 때 `useSns.localPosts`로, 좋아요 토글도 거기 적힌다. 컷은 `kind: 'npc'`로 내 저장소에.
    굽기(`bakeShot`·`sceneTypeFor`)는 .tsx라 스토어가 브라우저에서만 동적으로 올리고, 하네스는 `store.setNpcBaker`로 가짜를 꽂는다.
*   시계를 돌려(`jumpTo`) 건너뛴 활동은 tick의 gap 처리가 안 돌아 만화가 없다 — 엔진은 여유 있는 창에 들어설 때 오늘 끝난 활동을 먼저 정산한다(settle은 멱등). 초안은 책의 컷으로 만들어지므로.
*   **모델 문장은 뒤로 미룬다.** 캡션·고민 문장("하늘이랑 같이 찍힌 건데 올려도 돼?")·가상 친구의 캡션은 지금 규칙 기반이다(`agentPosts.captionOf`·`worryLine`·`npcCaptionOf`, TODO 표시). 채팅 프롬프트의 "왜 지금 올리는지" 한 줄도 아직 없다.
