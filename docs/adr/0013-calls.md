# ADR-0013: 전화는 약속한 것만 — 통보 전화를 없애고, 약속은 상황과 무관하게 지킨다

*   날짜: 2026-09-08
*   상태: 채택됨

## 배경

전화 구현을 훑어 보니(sim/call.ts · store.pumpCalls · chat.ts · CallOverlay) 걸려오는 전화의 출처가 셋이었다: 고민 쪽지에
답했을 때의 약속 전화, 채팅에서 지쳤다고 했을 때의 약속 전화, 그리고 **계획과 다른 곳에 도착했을 때의 통보 전화**.
오너는 셋째를 지우라고 했다 — 딴 데 간 사연은 시간표의 판단 줄과 활동 로그에 이미 남고, 그걸로 전화까지 거는 것은
방해다. 같이 확인된 구멍이 몇 개 더 있었다.

*   못 받는 상황(자는 중·기내·조용한 곳·식사)에서 "전화해줘"라고 하면 "나중에 내가 걸게"라고 답하고는 **아무것도 예약하지
    않았다.** SPEC의 "약속한 것은 지켜진다"와 어긋난다. 모델 답장의 `callMe`도 그 상황이면 버려졌다.
*   앱을 껐다 켜면 지난 tick 시각이 부팅 시각이라 첫 tick이 항상 "보고 있었다"가 됐다 — 비운 사이 시각이 지난 약속 전화가
    부재중이 아니라 **켜자마자 벨**로 울렸다.
*   지쳤다면서 걸어 달라고까지 해도 38분 뒤 고민 전화만 잡혔다(규칙·모델 둘 다).
*   통화 시간이 sim 초라 dev 배속에서 10배로 기록됐다. dev 프리뷰(`&call=`)의 가짜 통화는 닫을 수 없었다.

## 결정

1.  **에이전트가 먼저 거는 전화는 약속한 전화뿐이다.** 출처는 둘: 고민을 듣고("이따가 전화할게", 쪽지 칩이든 채팅이든
    38분 뒤), 걸어 달라고 해서("지금 걸게", 답장 뒤 20초). `pumpCalls`의 마찰 통보 갈래(`in:${act.key}`)는 지운다.
    `callLines`의 덧붙임 줄(통보 문장) 매개변수도 지운다.
2.  **약속은 상황과 무관하게 지킨다.** 못 받는 상황에서 걸어 달라는 말은 폰을 힐끗 보고(8분 안) "나중에 내가 걸게"라고
    답하고, **막힌 것이 끝나고 폰을 다시 본 뒤** 벨이 울린다 (`chat.askCallInMs`). 끝을 모르면 26분 뒤. 벨은 답장보다 먼저
    울리지 않는다. 규칙 답장과 모델 답장(`applyLlmReply`)이 같은 함수로 같은 시각을 잡는다 — 모델의 `callMe`를 더는
    버리지 않는다. 규칙이 이미 약속한 전화는 시각을 지키되 **종류는 모델이 올릴 수 있다** — 걸어 달란 전화(ask)를 고민
    전화로(고민도 메모리에 적는다), 38분 뒤 고민 전화를 곧으로.
3.  **지쳤다면서 걸어 달라고 하면 곧 거는 고민 전화다.** 38분을 기다리지 않고 답장 뒤 20초(못 받는 상황이면 2의 시각)에
    울리되, 통화 내용은 고민을 짚는 `worryLines`다. 규칙(`tired` + `call` 의도)과 모델(`worry` + `callMe`)이 같다.
4.  **비운 사이 시각이 지난 약속 전화는 부팅 때 부재중으로 접는다.** 10분 이상 비웠거나(`away`) 약속 자체가 10분 넘게
    지났으면(다른 기기·재로그인으로 받아 온 저장본엔 "마지막으로 본 시각"이 없다) `at <= now`인 약속을 내용 없는
    `missed` 기록으로 바꾸고 예약에서 지운다. `pumpCalls`도 약속 시각이 10분 넘게 지난 것은 벨 없이 부재중으로 적는다.
    잠깐 껐다 켠 것이면 첫 tick이 그대로 울린다. 지난 약속이 여럿이면 이른 것부터 tick마다 하나씩. 같은 자리에서, 받은
    채로 앱이 꺼진 통화는 마지막으로 본 시각까지(최대 1시간)로 끊은 것으로 친다 — 대화 실에 "통화 중"이 남지 않게.
    벨이 울리는 동안의 기록에는 내용(`lines`)을 넣지 않는다 — 받아야 붙는다.
5.  **통화 시간은 실제로 통화한 초다.** 화면이 붙어 있던 실제 시간을 재고, 검사 스크립트처럼 sim 시계만 점프했으면
    sim 경과(배속으로 나눈)를 쓴다. 배속을 통화 중에 바꿔도, 시계가 멈춰 있어도 실제 초가 남는다.
6.  **dev 프리뷰의 가짜 통화는 닫힌다.** `CallOverlay`에 `onDone`이 생기고 받기는 오버레이 안에서 받은 얼굴로 넘어간다.
7.  **받든 안 받든 기분·친밀도 수치는 건드리지 않는다.** 부재→기분은 백엔드 때 한다는 ADR-0004 결정 9를 따른다.
    받는 것의 값은 내용을 듣는 것이다.

## 결과

*   `sim/chat.ts`: `ChatReply.callInMs`, `askCallInMs()`, `GLANCE_MS`. `sim/store.ts`: 부팅 접기, `pumpCalls` 단순화,
    `sendMessage`/`applyLlmReply`가 `callInMs`를 쓴다, `endCall`이 배속을 나눈다. `sim/call.ts`: `callLines(placeType, seed)`.
*   백엔드 프롬프트(`ReplyPrompt`)는 못 받는 상황이면 "끝나고 걸게"라고 답하고, 힘들다는 말과 같이 오면 `worry`와
    `callMe`를 둘 다 적으라고 한다. 골든 파일 갱신. (모델 실행 검증은 오너 지시로 하지 않았다.)
*   검사: `scripts/sim-call.test.mjs`·`sim-chat.test.mjs`에 걸어 달란 전화가 실제로 울림, 못 받는 상황의 약속, 지침+전화,
    막힌 상태의 발신 거절, 배속 통화 시간, 우회 도착에 전화 없음, 모델 `callMe`의 뒤처리, 부팅 부재중(`sim-boot.test.mjs`).
*   SPEC·ADR-0001·ADR-0004·CONTRACT의 통보 전화 문장을 갱신했다.
