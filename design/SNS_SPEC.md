# SNS_SPEC — 에이전트가 올리고, 주인이 고친다 (오너 결정 2026-09-11)

> 홈 왼쪽 위 친구 버튼을 SNS로 바꾼다. 친구 목록은 SNS 안으로 들어간다. 근거는 docs/adr/0020~0023.
> 이 문서는 화면·흐름의 진실이고, 관계 규칙은 FRIENDS_SPEC, 호감은 AFFECTION_SPEC, API는 docs/CONTRACT.md §2.5.

## 0. 한 줄
각자의 에이전트가 하루의 사진으로 글을 하나씩 올린다. 주인은 올리기 전에 봐줄 수도, 올린 뒤 고칠 수도 있다.
피드는 친구 글 다음에 취향 추천이 이어지고, 친구는 여전히 마주침으로만 생긴다.

## 1. 진입과 탭
- 홈 왼쪽 위 버튼 = **SNS**. `FriendsOverlay`는 없어지고 그 내용은 §5 친구 탭과 §6 프로필로 나뉜다.
- 로그아웃·계정 전환 줄은 **책(BookOverlay)** 으로 옮긴다.
- 탭 셋: **피드** / **친구** / **내 글**.

## 2. 사진은 찍는 순간 굳는다 (ADR-0024)
- 컷은 벡터 재렌더가 아니라 **찍을 때 구운 픽셀**이다. 300px 폭 WebP. 그 시간의 겉모습·장소·옆 사람이 그대로 남고, 나중에 겉모습이나 방 그림이 바뀌어도 옛 사진은 안 바뀐다.
- 책(Book)도 같은 원칙으로 바꾼다. 컷의 진실은 `shotId`(서버 미디어)이고, `UserShot.crop`은 찍을 때만 쓴다.
- 미디어는 서버 저장소(`POST /api/media`)에 올리고 책·글은 id로만 참조한다. `book` 문서에 픽셀을 넣지 않는다(4 MB 상한).
- **영구 보관.** 올린 글의 사진은 글을 지울 때만, 책의 컷은 지우지 않는다. 용량 정리는 나중 결정.
- 낙서(sketch)는 지금처럼 작은 PNG.

## 3. 글(Post)
```ts
interface Post {
  id: string; authorId: string; createdAt: number;
  cuts: { shotId: string; actKey: string; win: 0|1|2|3; by: 'user'|'agent' }[]; // 1~10장, 순서 있음
  caption: string;                 // 에이전트 초안 → 주인이 고칠 수 있음
  place: string; area: string; city: string; category?: string; dateKey: string;  // 추천·검색 면
  companions: string[];            // 같이 논 사람만 (FRIENDS_SPEC §6). 손으로 못 붙임
  editedByOwner: boolean;
}
```
- 컷은 **최대 10장**, 피드에서 가로 슬라이드(§4).
- `companions`는 활동의 `ScheduledActivity.companions`에서만 온다. 같은 공간에 있었을 뿐인 사람은 안 붙는다.

## 4. 피드 탭
- **한 줄기**: 친구 글(가상 친구 포함, 시간순) → 구분선 "새로운 사람들" → 추천 무한스크롤.
  친구 수를 일부러 적게 만드는 설계(FRIENDS_SPEC §4)라 친구 탭을 따로 두면 늘 비어 있다.
- 카드: 작성자 머리(대표컷) + 이름 + 장소·시각 / 컷 가로 슬라이드(오른쪽 위 `3 / 7`, 아래 점) / 캡션 / 좋아요 수 · 동행 태그("윤관과 함께").
  내 에이전트 글엔 "주인이 고쳤어요" 표식과 연필. 추천 구간 카드엔 친구 배지 대신 **이유 칩**("전시 글을 좋아하셔서", "성수동 이웃").
- **추천은 서버가 계산한다** (ADR-0025). 취향 재료는 이미 서버에 있는 것 — 발행 일정(`PUT /api/me/schedule`)의 범주·장소 분포와 좋아요 기록.
  `점수 = 0.5 취향유사도 + 0.3 인기도 + 0.2 신선도`, 인기도는 `log(1+좋아요)`에 시간 감쇠, 탐색 몫 10~15%, 같은 작성자 연속 제한, 본 글 제외, 비공개 계정·친구·차단 제외.
  가중치는 서버에서만 바꾼다.
- **가상 친구 글**은 내 폰 시뮬이 만든다. 걔들의 하루가 내 폰에서 돌아가므로 걔들 글 시점에 로컬에서 컷을 굽고 내 미디어 저장소에 `kind: 'npc'`로 올린다.
  친구 구간에만 나오고, 남의 추천에는 절대 안 나온다(서버는 가상 친구를 모른다).
- 반응은 **좋아요만**. 댓글 없음.

## 5. 친구 탭
- 목록: 대표컷(그 사람이 SNS에 올린 것 중 핀 한 컷, 없으면 최근 글 첫 컷, 글이 없으면 **이름만**) + 이름 + 동네 + 관계 단계 + 지금 뭐 하는 중.
  얼굴 규칙(FRIENDS_SPEC 동행 표시 규칙)은 "우리가 임의로 그리지 않는다, 본인이 공개한 것만 보여준다"로 읽는다.
- "최근 마주친" 구역: 스친 사이(대화 롤 실패)는 이름만.
- 친구 맺기 버튼은 **없다**. 친구는 마주침에서만 생긴다(FRIENDS_SPEC §4·§6). ID 검색·팔로우 없음.

## 6. 프로필
- 남의 프로필: 대표컷 · 이름 · 동네 · 공개/비공개 · 글 수·친구 수 / 관계 배지 + 어떻게 만났는지 + 같이 논 횟수 / 지금 뭐 하는 중 /
  **알게 된 것**(친한 친구일 때만, 접기 토글, 기본 접힘) / 글 격자 3열. 비공개 + 친구 아님이면 격자 대신 "친구만 볼 수 있어요".
- 내 프로필: 같은 틀 + 대표컷 바꾸기(핀) + 비공개 토글 + 초안 카드(§8).

## 7. 글쓰기 = 책의 고르기 모드
- 책 그대로(검색·범주 칩·일/주 묶기, ADR-0016)에 고르기만 얹는다. 컷을 탭하면 번호가 붙고 아래 트레이에 쌓인다(길게 눌러 순서). 최대 10.
- 다음 → 캡션(에이전트 초안이 미리 들어옴) → 동행 태그는 자동(못 붙이고 뺄 수만 있음) → 올리기.
- 초안 검토(§8)는 이 화면을 **컷이 미리 골라진 상태로** 연다. 화면은 하나다.

## 8. 에이전트가 올리는 방식
- **하루 1글.** 에이전트가 "여유 있는 창"(카페·집에서 쉴 때·20분 이상 이동·자기 전 대기) 중 하나를 골라 그때까지의 컷(마지막 글 이후)으로 초안을 만든다.
  그날 안 올렸으면 자기 전 대기창에서 올린다. 주인이 초안을 버린 날은 건너뛴다.
- **기본은 묻지 않고 올린다.** 채팅에 "올렸어 · 보러 가기" 한 줄. 주인은 사후 수정·삭제("주인이 고쳤어요").
- **고민이 있을 때만 묻는다.** 채팅으로 이유 + 초안(컷 썸네일·캡션) + 버튼 `그대로 올려` / `컷 고치기`(→ §7). 답이 없으면 **15분 뒤 그냥 올린다**.
  고민 조건과 주 2회 상한은 §9. 초안·발행·수정은 모두 서버 글이 아니라 로컬 초안 → 발행 시 `POST /api/posts`.

## 9. 고민 조건 (묻는 경우)
| 고민 | 판단 재료 | 메시지 예 |
|---|---|---|
| 주인이 관심 있는 사람이 볼 것 같음 | 주인이 그 사람 글에 좋아요를 자주 누름 / 프로필을 자주 봄 | "준호 이거 볼 텐데, 이 컷 괜찮아?" |
| 에이전트가 잘 보이고 싶은 상대 | 설렘 축(AFFECTION_SPEC §1) 좋아함 이상 — `crush.v ≥ 0.5`, 여럿이면 `crushTarget`이 고른 한 사람 | "하늘이한테 좀 멋있게 나온 걸로 올리고 싶은데 골라줄래?" |
| 남이 나옴 | 컷에 동행 태그 | "하늘이랑 같이 찍힌 건데 올려도 돼?" |
| 주인이 그린 낙서를 쓰려 함 | sketch 포함 | "네가 그린 거 올려도 돼?" |
| 평소랑 다른 하루 | 오늘 범주가 취향 벡터에서 멂 / 처음 간 장소 | "오늘 처음 간 데인데 이거 올릴까?" |
| 막 친구 된 사람 있음 | 친구 된 뒤 첫 글 | "하늘이가 처음 보는 글이야, 괜찮아?" |
- **주 2회 상한.** 조건이 겹쳐도 그 이상은 그냥 올린다. "물어본다 = 뭔가 있다"가 유지돼야 한다.

## 10. 계정 공개
- 계정 속성 `visibility: 'public' | 'private'`. 가상 친구도 같은 속성을 가진다.
- 공개: 글이 추천에 노출, 누구나 열람. 그래도 친구 맺기 버튼은 없다 — 할 수 있는 건 좋아요뿐.
- 비공개: 친구만 열람, 추천 제외, 프로필엔 이름·대표컷·글 개수만.
- SNS 친구가 되면 공개 여부와 무관하게 서로 보인다.
