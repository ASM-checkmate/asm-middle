# ADR-0006: 말을 짓는 일만 백엔드로 보내고, 모델은 두 단계로 둔다

*   날짜: 2026-09-07
*   상태: 채택됨

## 배경

지금까지 앱은 프론트 하나였다. 시계·하루·판단·대화가 전부 브라우저의 시뮬레이션이고,
자유 텍스트의 해석은 정규식 열 개(`replyTo`)다. ADR-0002는 "LLM이 들어오면 이 함수만
갈아끼운다"고 자리를 비워 뒀고, ADR-0005까지 오니 대화가 "언제 읽고 언제 답하는가"는
사람 같아졌는데 **무슨 말을 하는가**가 여전히 봇이다 (모르는 말은 전부 "잘 모르겠다").

세 가지를 정해야 한다. 무엇을 백엔드로 보낼지, 어떤 언어로 만들지, 어떤 모델을 쓸지.

## 결정

**"무엇을 말할지"만 백엔드로 보낸다. 백엔드는 의존성 0의 Node/TypeScript 서버이고,
모델은 로컬 Ollama의 두 단계 — small(`qwen3.5:9b`)과 good(`qwen3.8:27b`) — 를 골라 쓴다.**

1.  **시간은 프론트, 말은 백엔드.** 읽는 시각·답하는 시각·읽씹·묶음(ADR-0005)은 전부
    `sim/chat.ts`의 규칙 그대로다. 백엔드는 묶음 하나에 "뭐라고 답할지"(`text`)와 규칙이
    못 알아들었을 수 있는 두 가지(`worry`, `callMe`)만 돌려준다. 계약은 `docs/CONTRACT.md`.
2.  **규칙 답장이 항상 먼저 저장되고, 모델 답장은 그것을 갈아끼운다.** 보내는 순간 규칙
    답장이 미래 시각을 달고 저장된다(ADR-0002). 백엔드가 그 시각 전에 답하면 말만 바꾸고,
    늦거나 죽었으면 규칙 답장이 그대로 뜬다. 사용자가 본 적 있는 답장은 절대 바뀌지 않는다.
    묶음에 말이 더 붙었으면(`seq` 불일치) 늦게 온 답장은 버린다.
3.  **백엔드는 Node 24 + TypeScript, 의존성 0.** `node:http`와 `fetch`만 쓰고 Node가 .ts를
    그대로 돌린다. 두 패키지는 서로를 import하지 않고 계약 타입을 복사해 둔다.
4.  **모델은 두 단계.** `?dev=1` 패널에서 `off · small · good`을 고른다. 기본은 off —
    백엔드 없는 사람도 앱이 그대로 돈다. 생각(thinking) 모드는 끈다.
5.  **시뮬레이션은 아직 옮기지 않는다.** 시계·하루·판단이 브라우저에 남는다. 이 ADR은
    분리의 첫 칸이지 전부가 아니다.

## 근거

*   **왜 Node인가.** 시뮬레이션이 TypeScript 1만 2천 줄이고 팀의 프론트도 TS다. 나중에
    시뮬레이션을 서버로 옮길 때 같은 코드를 쓸 수 있다. A2A의 Spring Boot는 제품 레포의
    결정이고, 이 레포(프로토타입)에서 Java로 다시 쓰는 것은 그때 가서 정할 일이다.
*   **왜 의존성 0인가.** handbook의 의존성 규칙이 아직 미결이다. 관문 하나에 프레임워크는
    필요 없다.
*   **왜 시간을 모델에 안 맡기는가.** 읽씹·안읽씹·묶음은 결정적이어야 검사할 수 있고,
    새로고침해도 같은 대화여야 한다. 모델은 시계를 모른다. 말만 맡기면 모델이 죽어도
    대화의 리듬은 남는다.
*   **왜 두 단계인가.** 27B는 M5 Pro 48GB에서 16 tok/s(4-bit)로 한 줄에 2~4초, 첫 로드
    5초다. 실시간 채팅엔 충분하지만 배터리와 메모리 18GB를 먹는다. 9B는 6.6GB에 세 배
    빠르다. 둘을 나란히 두고 **어느 쪽이 "친구"로 읽히는지** 비교하는 것이 목적이다.
*   **왜 이 모델들인가.** Artificial Analysis 오픈 웨이트 4B–40B 순위에서 Qwen3.8 27B가
    1위(지능 지수 34–41), 10B 아래에서는 Qwen3.5 9B(32)가 다음 모델의 두 배다. 둘 다
    Apache 2.0, 256K 컨텍스트, Ollama에 그대로 있다. 한국어 반말은 벤치에 없으므로
    실제 답장으로 본다 (Gemma 4 E4B도 한국어는 좋았지만 지수 15).
*   **버린 선택지 — 모델 답장을 기다렸다가 저장.** 서버가 죽으면 답장이 영영 안 온다.
    규칙 답장을 먼저 저장하는 것이 ADR-0002의 "이미 저장돼 있고 아직 시각이 안 된 것"과
    같은 원리다.
*   **버린 선택지 — 브라우저에서 Ollama 직접 호출.** CORS 설정을 사용자에게 시키게 되고,
    프롬프트가 프론트에 박힌다. 관문이 있어야 나중에 원격 모델로 바꿀 수 있다.

## 영향

*   레포에 `backend/`가 생긴다. 실행: `backend/README.md`. 프론트 개발 서버가 `/api`를
    프록시한다 (`vite.config.ts`).
*   `docs/CONTRACT.md`가 API의 단일 진실이다.
*   `ChatMsg`·저장 형식은 그대로다. 새 localStorage 키 `theworld.llm.v1`(단계) 하나.
*   감수하는 트레이드오프
    *   **답장이 두 번 만들어진다.** 규칙 답장은 버려지는 경우가 대부분이다. 대신 실패
        경로가 없다.
    *   **모델이 상황을 틀릴 수 있다.** 위치·하는 일은 프롬프트로 못 박지만, 작은 모델은
        가끔 지어낸다. good 단계와 비교하는 것이 이번 실험의 일부다.
    *   **첫 답장이 느리다.** 모델 로드 3~5초. `keep_alive` 30분으로 두 번째부터는 없다.
