# ADR-0007: 그림은 비전 모델이 읽고, 못 읽으면 지금처럼 고백한다

*   날짜: 2026-09-07
*   상태: 채택됨

## 배경

ADR-0004로 사용자는 그림으로 계획을 넘길 수 있게 됐지만, 규칙 기반이라 **그림을 하나도
읽지 않는다.** 무엇을 그리든 같은 시드는 같은 결과이고, 출발 줄의 "그림은 못 알아봐서 내
맘대로 골랐어"가 그 선을 지키는 유일한 장치였다. ADR-0004는 "알아보는 모델이 들어오면
`sketchBlock` 뒤의 선택 한 자리만 바꾼다"고 자리를 비워 뒀다.

ADR-0006으로 로컬 모델 관문이 생겼고, 받아 둔 두 모델(Qwen3.8 27B · Qwen3.5 9B) 모두
비전을 받는다. 그 자리를 채울 수 있다.

## 결정

**그림을 넘기는 순간 백엔드가 비전 모델로 읽어 "어느 카드인가"를 계획에 적어 두고, 블록이
시작하면 그 카드를 먼저 고른다. 못 읽으면 지금 그대로다.**

1.  **미리 읽는다.** `sketchBlock` 직후 `POST /api/sketch/read`에 그림과 그 블록의 카드
    3장을 보낸다. 답(`optionId`·`seen`)은 `plan.sketchRead`에 적힌다. 블록 시작(`decide`)은
    동기라 그때 기다릴 수 없고, 그림은 아침에 넘기고 블록은 몇 시간 뒤에 시작한다.
2.  **비밀은 그대로다.** `sketchRead`는 화면 어디에도 안 나온다. 시간표는 여전히
    "그림으로 넘김"이고, 예고도 판정 카드도 없다 (ADR-0004 §5).
3.  **같은 문을 지난다.** 알아본 카드도 돈·피로 검문(`review`)에 막히면 못 고른다. 그때는
    시드로 고르고 못 알아본 것과 같은 고백이 남는다.
4.  **알아본 날의 출발 줄이 바뀐다.** "컵 그린 거지? 알아봤어. 이걸로 간다" (`narrate`의
    `sketch-seen`). 못 알아본 날은 지금의 `sketch-pick` 그대로다.
5.  **모르면 null.** 프롬프트와 스키마가 "확신 없으면 null"을 못 박는다. 아는 척한 오답보다
    고백이 낫다는 ADR-0004 §8의 원칙이다.
6.  **그림이 바뀌면 버린다.** 답이 도착했을 때 그림이 다시 그려졌거나 카드로 돌아갔거나 이미
    시작했으면 적지 않는다. 카드 경로는 `sketch`와 함께 `sketchRead`도 지운다.

## 근거

*   **왜 카드 3장 중 고르기인가.** 자유 인식("이게 뭐야")보다 훨씬 쉬운 문제다. 모델 선정은
    Quick, Draw! 낙서 200장(20종 × 10장)을 앱 스타일(코랄 붓, 종이 바탕, 240px)로 다시
    그려 20개 보기 중 고르게 한 결과로 했다 (2026-09-07, M5 Pro 48GB, Q4_K_M, think off,
    temperature 0):

    | 모델 | 정확도 | "모르겠다" | 장당 |
    |---|---|---|---|
    | qwen3.5:9b | 84% | 3 | 0.50초 |
    | qwen3.5:4b | 81% | 0 | 0.33초 |
    | qwen3.5:2b | 80% | 0 | 0.19초 |
    | gemma4:12b | 80% | 0 | 0.74초 |
    | qwen3.8:27b | 73% | 0 | 1.62초 |
    | gemma4:e4b | 71% | 39 | 0.38초 |

    프롬프트를 한국어로 바꿔도 같다 (9B 84%, 27B 69%). 낙서 인식은 언어 모델 크기를
    따라가지 않는다 — 27B가 9B보다 못하다. 틀린 것의 대부분은
    사람이 봐도 애매한 침대·자전거 낙서다. 실제 문제는 3지선다에 "모르면 null"이라 이보다
    쉽고, 카드 3장 실험에서는 9B가 한 번 아닌 것을 골랐고(산→자전거) 27B는 모르는 건 다
    null로 뒀다. 그래서 단계 매핑은 대화와 같게 두고(small=9B, good=27B) 앱에서 비교한다.
    Artificial Analysis의 이미지 리더보드는 **생성** 모델 순위라 여기엔 쓸 수 없었다.
*   **왜 시드 선택을 없애지 않는가.** 서버가 없거나 모델이 모르겠다고 하면 지금 경로가
    그대로 돈다. ADR-0006의 "규칙 답장을 먼저 저장"과 같은 실패 경로다.
*   **버린 선택지 — 블록 시작 때 읽기.** `decide`를 비동기로 만들면 타임라인 계산 전체가
    비동기가 된다. 미리 읽어 두면 그럴 필요가 없다.
*   **버린 선택지 — 알아본 걸 시간표에 보여 주기.** "컵이네요, 카페 가요"를 보여 주면
    그림이 카드 하나로 환원된다 (ADR-0004의 "왜 비밀인가").

## 영향

*   `BlockPlan.sketchRead`, `ScheduledActivity.sketchSeen`이 생긴다 (선택 필드, 저장 버전
    그대로). `narrate`에 `sketch-seen` 갈래. 계약은 `docs/CONTRACT.md`.
*   `?dev=1`의 llm 단계가 off면 읽지 않는다 — 그림 경로는 ADR-0004 그대로다.
*   감수하는 트레이드오프
    *   **오답이 생긴다.** 규칙 기반은 틀릴 수 없었다(안 읽으니까). 이제 "컵 그린 거지?"
        하고 자전거를 그린 사람을 카페에 보낼 수 있다. null을 강하게 권하는 프롬프트와
        good 단계(27B)로 줄이되, 없앨 수는 없다.
    *   **그림이 백엔드로 나간다.** 로컬 Ollama라 밖으로는 안 나가지만, 원격 모델로 바꾸는
        날엔 사용자의 그림이 나가는 것이다.
